# ANTI-EXTRACTION RULES

> Rules preventing value capture at the expense of the system.

## Core Principle

**Value should circulate, not accumulate.**

Extraction is any pattern where value flows OUT of the system faster than it flows IN,
or where value concentrates instead of distributing.

---

## Detection Patterns

### 1. Yield-Only Optimization
**Signal:** An action improves yield but provides no coherence, circulation, or resilience benefit.

**Rule:** Actions with yield as the ONLY benefit are flagged as potentially extractive.

---

### 2. Stress-Despite-Gains
**Signal:** Apprentice stress increases even though their capabilities are growing.

**Rule:** If `stress_trend = increasing` while `capability_trend = increasing`, 
the loop structure may be extractive. Flag for review.

---

### 3. Value Hoarding
**Signal:** Resources concentrate instead of flowing to where they're needed.

**Rule:** If `circulation_impact < 0` for any action, it may be extractive.
Block unless higher-priority benefit exists.

---

### 4. Relationship Decay
**Signal:** Trust levels declining across relationships despite activity.

**Rule:** If `trust_level` decreasing across multiple relationships,
investigate for extractive patterns.

---

## Protective Mechanisms

### For Apprentices
- Phase transitions require demonstrated mutual benefit
- Stress monitoring triggers automatic intervention
- Capability gains must correlate with reduced oversight

### For Capital
- Speculative allocation blocked by default
- Position sizes limited to 20% of portfolio
- All debt requires resolution path

### For Relationships
- Trust decay triggers review
- Override patterns trigger calibration review
- Communication must be bidirectional

---

## The Alice Test

> "If this pattern continues, will the human emerge stronger and more autonomous, 
> or depleted and dependent?"

Every loop should pass the Alice Test - named after the first successful transformation
from $7/hour to $10k/month partner. If a loop would fail Alice, it's extractive.
