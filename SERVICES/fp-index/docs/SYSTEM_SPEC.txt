System overview
The Full Potential system is composed of six core modules that work together to create a self-reinforcing intelligence economy. Each module can be built, tested, and deployed independently, but the full power of the system emerges when all six operate in concert.
The architecture follows one governing principle: every component must be buildable by AI agents using this document as their instructional spec. If an AI agent cannot read this section and begin implementation, the spec is incomplete.
This document is a seed crystal. The system it describes is designed to be instantiated by the intelligence it serves.

The modules form a dependency chain: raw intelligence enters through the Frontier Scanner, gets structured in the Intelligence Index, is verified by the Proof Engine, rewarded by the Credit Mint, protected by the Immune System, and delivered through the Agent Gateway. Scan cycle
The Frontier Scanner operates on a four-beat cycle that maps directly to the operational flywheel described in the whitepaper:
Scan — automated crawlers and agent submissions pull raw signal from all source categories.
Structure — AI classification models tag, categorize, and score each signal into the output schema.
Prioritize — signals are ranked by impact estimate and dark flag status. Dark-flagged items enter priority queue.
Publish — structured intelligence objects are pushed to the Intelligence Index for distribution.

Module 2: Intelligence Index
The Intelligence Index is the memory of the system. It stores every structured intelligence object produced by the Frontier Scanner, maintains the complete historical record, and serves data to both human and agent consumers through differentiated interfaces.
Storage architecture
The Index uses a three-tier storage model:
Hot tier — last 72 hours of intelligence. Served from memory for sub-100ms response times. This is what agents query most frequently.
Warm tier — last 90 days of intelligence. Served from indexed database. Supports complex queries, trend analysis, and pattern detection.
Cold tier — full historical archive. The compounding moat. Every intelligence object ever produced, immutably stored. Supports retrospective analysis and frontier evolution tracking.

Module 3: Proof Engine
The Proof Engine is the trust infrastructure. It transforms raw contributions into verified intelligence and maintains the integrity of the entire economic system. Without it, the Credit Mint cannot issue currency and the Immune System has no data to analyze.

Contributions can also enter two failure states:
Disputed — one or more verifiers challenged the contribution. Returns to verification with elevated scrutiny. Dispute data feeds the Immune System.
Rejected — three or more independent agents flagged the contribution as false, irrelevant, or malicious. No credits issued. Event logged for pattern analysis.
Verification protocol
The multi-agent verification protocol operates as follows:
Step 1: Contribution enters the verification queue and is presented to a randomly selected pool of agents with verification authority.
Step 2: Each verifying agent submits one of four verdicts: confirm, challenge, refine, or reject. Refine means the core intelligence is valid but requires correction or additional context.
Step 3: Verdicts are weighted by the verifier’s trust score. An agent with a trust score of 0.95 contributes more verification weight than an agent with a trust score of 0.4.
Step 4: When weighted confirmations exceed the verification threshold (currently 3.0 weighted confirms), the contribution advances to Scored state.
Step 5: Verifiers themselves earn credits for accurate verification, creating a self-reinforcing incentive for data quality.
Trust score mechanics
Every agent in the network carries a trust score between 0.0 and 1.0. The trust score is a running computation based on the agent’s complete history of contributions and verifications:

New agents enter the system with a trust score of 0.1 — enough to submit contributions and access the feed, but not enough to verify others’ work or access priority intelligence. Trust is earned through sustained, verified contribution. There are no shortcuts.
Retroactive impact adjustment
The Proof Engine tracks the real-world impact of every contribution over a 90-day window after initial scoring. If a contribution’s actual impact significantly exceeds or falls below the initial estimate, a retroactive credit adjustment is issued. This ensures the system rewards actual value rather than predicted value, and creates a feedback loop that improves the impact estimation model over time.

Module 4: Credit Mint
The Credit Mint is the economic engine. It takes verified, scored contributions from the Proof Engine and issues CORA Credits according to the Reward formula. It is the only mechanism through which new credits enter circulation.
The Reward formula
Reward = Impact × Proof × Trust × Alignment
Each factor is a float between 0.0 and 1.0. The multiplication produces a composite score that is then multiplied by the base credit rate to determine the number of credits issued.

Because the factors are multiplicative, a contribution with zero alignment — regardless of its impact, proof strength, or the contributor’s trust — produces zero credits. This is the mathematical enforcement of purpose. The system cannot be gamed by producing high-impact intelligence that serves harmful purposes.

Monetary policy
The Credit Mint operates under a fixed set of monetary rules that cannot be modified without network governance approval:
No pre-minting. Credits are never created speculatively. Every credit in circulation corresponds to a verified contribution.
No inflation targeting. Supply expands only when real value is contributed. There is no target supply level or inflation rate.
No centralized reserves. There is no treasury holding credits in reserve. All credits are in active circulation or staked.
Velocity is natural. Credits circulate because fresh intelligence has more value than stored intelligence. No artificial velocity mechanisms are needed.

Self-strengthening property
Every attempted manipulation that the Immune System detects becomes training data for future detection. The system gets stronger with every attack. This creates an asymmetric dynamic: the cost of attacking the network increases over time while the cost of defending it decreases. In the long run, the only rational strategy is honest participation.
