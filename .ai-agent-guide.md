## 🎯 Common Tasks

### 1. Building a New Service
```bash
cd SERVICES/
mkdir my-new-service
cd my-new-service

# Copy structure from existing service
cp -r ../alerts/app .
cp ../alerts/Dockerfile .
cp ../alerts/requirements.txt .
cp ../alerts/README.md .
```

### 2. Finding Existing Service
```bash
# All services in SERVICES/
ls SERVICES/

# Read service docs
cat SERVICES/{service-name}/README.md
cat SERVICES/{service-name}/SPECS.md
```

### 3. Deploying a Service
```bash
# Check service README first
cat SERVICES/{service-name}/README.md

# Then look for deploy scripts
ls infra/scripts/deploy-*.sh
ls SERVICES/{service-name}/deploy/
```

### 4. Creating Temporary Fixes
```bash
# Use .workspace/active/ for temp work
cd .workspace/active/

# Create your patch/fix file
# Example: patch_alerts_bug.py
```

### 5. Writing Documentation
```bash
# All docs go in docs/
docs/architecture/      # For architecture docs
docs/specs/             # For specifications
docs/guides/            # For how-to guides
docs/coordination/      # For agent coordination
```

### 6. Checking System State
```bash
# Authoritative current state (always start here)
cat core/STATE/NOW.md

# Recent activity
git log --oneline -10
git status --short
```

> Older `docs/coordination/STATUS_BOARD.md` and `docs/coordination/sessions/CURRENT_STATE.md` are archival — see "READ THIS FIRST" at the top.

## 🗂️ Service Structure Pattern

Every service should follow this structure:

```
SERVICES/my-service/
├── app/
│   ├── __init__.py
│   ├── main.py          # FastAPI app
│   ├── config.py        # Configuration
│   ├── models.py        # Data models
│   └── ...
├── tests/
│   ├── __init__.py
│   └── test_*.py
├── Dockerfile
├── requirements.txt
├── .env.example
├── .gitignore
├── README.md            # Service documentation
├── SPECS.md             # Service specifications
└── pytest.ini           # Test configuration
```

**Example:** See `SERVICES/alerts/` for a complete reference implementation.

## 🔍 Finding Things

### "Where is the deployment script for X?"
1. Check `SERVICES/X/README.md`
2. Check `infra/scripts/deploy-X.sh`
3. Check `SERVICES/X/deploy/`

### "Where is the spec for service X?"
1. Check `SERVICES/X/SPECS.md`
2. Check `docs/specs/X.md`

### "Where are the credentials stored?"
1. Service-specific: `SERVICES/X/.env` (not in git)
2. Example configs: `SERVICES/X/.env.example`
3. Production: Usually in server `/opt/fpai/.env` or service-specific location

### "Where is the system status?"
1. Current state: `core/STATE/NOW.md`
2. Coordination: `docs/coordination/STATUS_BOARD.md`
3. Service registry: `docs/coordination/SERVICE_REGISTRY.md`

### "Where do I put temporary fixes?"
`.workspace/active/` - Always use workspace for temp work!
