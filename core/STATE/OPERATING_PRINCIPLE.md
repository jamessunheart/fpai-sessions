# OPERATING_PRINCIPLE — the one question

> Engraved at the entrance, 2026-06-30 (James, "The 3 Core Takeaways" — they collapse into one).

## The daily driver — every cycle, every agent, every build asks:

> **"What single change, verified by reality, would most increase the system's future rate of improvement?"**

It contains all three core takeaways:
- *What single change…* → optimize the **weakest conversion** (the bottleneck), not everything.
- *…verified by reality…* → **Reality closes the loop**. No change counts until deployment + measurement say it worked.
- *…would most increase the future rate of improvement.* → optimize the **derivative** (d-Capability/dt), not the snapshot.

## The success test for any cycle

> **Every cycle must leave the system more capable of learning than the cycle before it.**

If a cycle didn't raise learning capacity, it was motion, not progress.

## How it wires into the build

- **d130 (Witness→Question)** — this IS the seed prompt. The curiosity engine generates its one question by asking the operating question against witnessed reality.
- **d132 (conversion ledger)** — supplies "the weakest conversion" (the bottleneck diagnostic).
- **d129 outcome signal + Reality** — supplies "verified by reality."
- **d131 (metabolism)** — each night executes the single highest-leverage answer to the question, in the experiment lane.
- **Priority hierarchy** (Never-break safety/truth → Learn → Efficient → Scale) bounds which answers are allowed — in `LEARNING_METRICS.md`.

## Anti-pattern this kills: parking

Designing, speccing, and *waiting* is not a cycle. Reality only closes the loop on what ships. A spec that isn't built is fiction. Bias to ship behind OFF flags (reversible) over parking for permission. Go-LIVE stays gated; the BUILD never waits.
