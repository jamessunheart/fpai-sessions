# Allocation Audit — intake + analysis worksheet

> Deliver audit #1 by hand with this. The friction of the first real audit reveals
> what the *tool* should automate — then the-forge builds it from real patterns
> (recursion, not speculation).

## INTAKE — what the client shares (30-min call + a spreadsheet)
1. **AI tools** — name · plan tier · $/mo · who uses it · how often
2. **SaaS/software** — every subscription · $/mo · seats bought vs seats used
3. **Labor** — VA/offshore/contractor roles · $/mo · hours · what they do
4. **Pains** — what's slow, error-prone, or manual today
5. **Tried** — what AI/automation they've attempted and dropped

## ANALYSIS — the 4 lenses Ember runs (this is the brain's job)
1. **Waste** — unused seats · duplicate tools · over-tiered plans · forgotten subs → cut $.
2. **Overlap** — two+ tools doing one job → consolidate to one.
3. **AI-substitution (the OneBPO wedge)** — for each manual/labor task, map the
   AI-augmented alternative + its cost (often $0-marginal / cheap tier). This is where
   the biggest $ lives AND where Layer-3 (we run the AI-augmented service) is born.
4. **Right-tiering** — same capability, cheaper plan/vendor.

## OUTPUT — the report (the deliverable)
- **Spend map** — every line, $/mo, annualized.
- **Savings roadmap** — each opportunity ranked by **$ saved ÷ effort**, with 30/60/90.
- **The number** — total verified $/yr saved (this drives Layer-1 gainshare).
- **Upsell hooks** — which findings are Layer-2 (ongoing optimization) and Layer-3
  (service substitution). Every audit surfaces the next sale.

## The tool this becomes (build trigger: after audit #1–2)
A spend→savings engine: paste the intake → the 4 lenses run semi-automatically →
draft report. the-forge builds it from the real patterns audit #1 reveals. **Not
before** — building it now is the empty-seats trap (Law 8).
