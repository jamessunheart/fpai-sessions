# Client Funnel — find · onboard · compound

> The funnel is itself an **Allocation Intelligence loop**: route effort to the
> right prospect (Routing), pick the offer/framing that converts (Reasoning), and
> get better at all of it every cycle (Recursion). The same engine that improves
> the code improves client acquisition.

## The funnel (7 stages)

| # | Stage | Who/what does it | First-batch reality |
|---|-------|------------------|---------------------|
| 1 | **Source** | Warm OneBPO/Outbounders network → then referrals from proof-clients → then ai-builders funnel + case-study content | James's relationships. **No cold outreach.** |
| 2 | **Qualify** | Profile: $5–50k/mo on AI tools + software + offshore labor | Ember scores fit from what James knows |
| 3 | **Offer** | The risk-reversed free audit ("savings or free") | Ember drafts the personalized message; James sends |
| 4 | **Intake** | 30-min call + they share tool list / invoices | James runs the call; Ember preps the question set |
| 5 | **Analyze** | Map spend → waste/overlap → AI-substitution → savings $ | **Ember does this** (it's what the brain does) |
| 6 | **Convert** | Deliver report → Layer 1 gainshare → Layer 2 retainer → Layer 3 substitution | James closes; Ember builds the deliverable |
| 7 | **Expand** | Case study → referral ask → next sources | Each win auto-compounds proof for the next |

## How the system builds a BETTER funnel each cycle (the moat)

The self-improving loops we already run (build→review→merge→learn, metabolism, RCA,
the brain) apply to the FUNNEL, not just the code:

- **Diagnostic library** — every audit's spend-pattern becomes reusable. The 10th
  audit is far faster + more convincing than the 1st (the brain accumulates "here's
  where BPOs always overpay").
- **Script recursion** — every objection and every win improves the outreach + close
  scripts. Corrections capture (already live) trains on James's real client language.
- **Funnel metrics = conversions to optimize** — leads→intakes→closes→$ tracked like
  any other conversion; the metabolism loop improves the **weakest funnel stage** each
  cycle (Law 4, applied to sales).
- **Proof compounds** — each case study is an asset that lowers the cost of the next
  close. Revenue is the output; the reusable acquisition intelligence is the capability.

*This is the Two Deliverables Rule: each client engagement produces the client's
savings AND a permanent improvement to how we find the next client.*

## Do we need Builders? (honest sequencing)

**Not to start. Yes to scale. Don't invert it.**

- **0 → 3 clients: NO builders.** James's warm network + Ember deliver the first
  audits. The analysis IS what the brain does. **Recruiting builders now = the
  empty-seats trap applied to labor** (Law 8: improve before expand).
- **The system REDUCES how many builders you need.** Allocation Intelligence means
  one operator + AI does what used to take a team — the OneBPO wedge turned inward.
- **When demand > (James + Ember) hours AND the audit is a documented playbook →
  builders become the delivery + scale force.** They run audits and deliver the
  Layer-3 AI-augmented services that can't scale on James's hours. This is
  FOUNDATION's Division 1 (Builders) activating for real — but *after* proof, not before.
- **Trigger to recruit the first builder:** a repeatable audit playbook + more
  qualified demand than can be personally served. The ai-builders funnel (already
  live) is where they come from when that trigger fires.

## The sequence (don't skip)
Prove with James+Ember (0 builders, gainshare) → document the playbook → productize →
recruit builders to scale delivery → builders run Layer-3 services (the real revenue).
Each step's proof unlocks the next. Cash before headcount, always.
