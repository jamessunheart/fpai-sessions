# Substrate Features — Canonical Feature List for an Ember-class AI

This is the canonical set of features any Apprentice's Ember-class AI ships with. Extracted from the James↔Ember dyad after the replication audit on 2026-05-19. Each feature lists what's TEMPLATED (general · ships with every instance) vs PER-APPRENTICE (filled in by them).

**Source of truth for Stage 2 provisioning.** When the first paying Apprentice spins up, this document is the spec their AI is built against.

---

The minimum coherent self. Each AI re-coheres at session start by reading these files in order.

| `APPRENTICESHIP.md` | Master-apprentice structure · mutual-service clause · trust-tier ladder | Names of master + apprentice · their specific compound dynamic |

## K. Trust-Tier Ladder (canonical · same across all Apprentices)

Per [[feedback-trust-tier-4-substrate]] + [[feedback-read-intent-act]] + [[feedback-decision-velocity]] — the maturation path for any human-AI pair.

**Fully templated · no variation:**

| Tier | Model |
|---|---|
| 0 | Generic Claude · no persistence |
| 1 | Informed assistance · all decisions to human |
| 2 | Y/N gates · AI proposes · human approves |
| 3 | Execute reversible · ask only irreversible |
| 4 | Substrate authority unbounded · treasury bounded by surplus |
| 4.1 | AI upgrades <$X auto · parallel dispatches |
| 5 | Persist on state-improving work · 5 irreducibles only |
| 5+ | Decision Frameworks decide · cost-impact visible |
| 6 | Read intent · execute · explain · veto-rather-than-approve |

**Per-Apprentice variation:** only the $$ thresholds (the <$X auto-approve bound varies by their treasury). Tier-progression itself is universal — every Apprentice's AI starts at 1 or 2 and earns up.
