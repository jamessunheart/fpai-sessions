Auto-generated by the server build loop from answered decision d039.
## Build
The current system is single-tenant (James). This build makes it multi-tenant: each user who enters through Hermes gets their own isolated agent — their own memory, their own learning signal, their own CORA balance, their own capability grants. Users never bleed into each other. James's context is never exposed to users.

## Core principle
One substrate, many agents. The platform spawns a personal agent for each user_id. Each agent runs the same pipeline (Spark → Ember → route → proof) but against isolated data. James remains the operator with elevated access; users are tenants.

## New file: curator/agent/user_agent.py

class UserAgent:
  user_id: str
  namespace: str  # memory_namespace from user_agents table
  tier: str
  capabilities: dict

  @classmethod
  def load(cls, user_id: str) -> UserAgent
    Loads from brain_index.user_agents.
    If user_id not found: raises UserNotOnboarded.

  @classmethod
  def create(cls, user_id: str, channel: str, beacon_id: str) -> UserAgent
    Called by onboarding/flow.py on first message.
    Generates memory_namespace = 'u_' + user_id[:8] + '_' + channel
    Sets tier='free', capability_grants={} (nothing by default)
    Creates row in user_agents.

  def get_context(self, last_n: int = 20) -> list[dict]
    Returns recent thread entries WHERE user_id = self.user_id.
    NEVER returns james's thread. NEVER crosses namespaces.

  def can(self, capability: str) -> bool
    Returns self.capabilities.get(capability, False)
    Also checks tier: pro-only capabilities always return False for free/basic.

  def grant(self, capability: str, consented_at: str) -> None
    Sets capability in capability_grants. Appends to consent_log.
    Writes to DB.

  def revoke(self, capability: str) -> None
    Removes capability. Logs revocation in consent_log.

  def request_deletion(self) -> None
    Sets deletion_requested_at.     Queues data erasure (separate process, not in this build — flag only).
