## Build
The system has no way to find its own users. Everything is inbound: someone has to arrive at the bot. The next unlock is outbound: the system identifies real people, initiates a genuine conversation, hands off to the bot, and learns from every response. Growth rate is not fixed — it is governed by signal quality. When conversations go well, it reaches more people. When it struggles, it pulls back and fixes first.

## Core principle: optimized growth rate, not arbitrary cap
No fixed number of outreach per period. Rate is governed by:
  1. System health: smoke tests passing → outreach can run; any FAIL → pause outreach until resolved
  2. Conversation completion rate: % of initiated conversations that reach a meaningful exchange
     - If completion >= 60%: scale up (double outreach rate next cycle)
     - If completion 30-60%: hold rate, fix routing gaps first
     - If completion < 30%: pause outreach, surface gaps to council
  3. Correction frequency: if James corrects bot behavior > N times/day from probe conversations → slow down
  4. Response quality score: claude -p evaluates each completed conversation for routing accuracy
The system itself decides how fast to grow based on how well it is handling what it already has.

## Outreach pools (ordered by trust — start with warmest)
Pool 1 (warm): James's existing contacts — people who already know him or the game
  Source: brain_index.user_profiles WHERE source='warm_list'
  Approach: direct, transparent — 'I'm testing an AI system, would you spend 5 min with it?'
Pool 2 (adjacent): people in Full Potential Game adjacent communities
  Source: manually seeded list (James adds handles/contacts to brain_index.probe_pool)
  Approach: genuine curiosity — 'What are you working on?' — not a pitch
Pool 3 (cold): public communities where James's system would be genuinely useful
  Source: defined by James (subreddits, Telegram groups, Discord servers)
  Approach: contribute value first, invite to the bot if they engage
Probe only moves to Pool 2 when Pool 1 completion rate > 60%. Only to Pool 3 when Pool 2 > 60%.

## What a probe conversation looks like
The Probe does NOT pitch. It asks one genuine question.
Example opener: 'Hey — I'm building an AI system that helps people figure out what they're actually working toward. Would you be willing to spend 5 minutes talking to it? I'm looking for honest reactions.'
If they say yes: give them the bot link or handle (@sunheartbrain_bot)
If they ask what it does: one sentence — 'It asks 3 questions and tries to point you toward one clear next step.'
No features, no pitch, no upsell. The conversation with the bot is the product.

## Signal capture (what the system learns)
For each probe conversation:
  - Did they engage with the bot? (yes/no)
  - At what point did they stop? (which message number)
  - What was the last message (their input or the bot's response that caused drop-off)
  - Did they complete Spark routing? (yes/no)
  - Did they reach a proof or action step? (yes/no)
  - Corrections triggered: any James corrections during or after this conversation
All stored in brain_index.probe_sessions (new table).

## Rate governor: tools/probe/rate_governor.py
Runs before each probe cycle to determine outreach count for this cycle:
  1. Check smoke tests: any FAIL in last 6h -> return 0 (pause)
  2. Check correction frequency: > 5 corrections today -> return 0 (pause)
  3. Read last 7 days probe_sessions completion rate
  4. Apply rate rule:
     - No history yet: start with 3
     - completion >= 60%: last_rate * 2 (double, cap at 50/cycle)
     - completion 30-60%: last_rate (hold)
     - completion < 30%: 0 (pause, surface gap to council)
  5. Log rate decision to ops_ledger: event=probe_rate, count={n}, reason={why}

## New file: tools/probe/agent.py

## Conversation quality evaluation
After a probe conversation reaches a natural end (no response in 24h):
  Run claude -p (--effort medium):
    'Rate this conversation 0.0-1.0 for: (1) did Spark route them clearly,     (2) did they seem to understand what to do next, (3) did anything confuse them.     JSON: {score: float, gaps: [str], highlight: str}'
  Store in probe_sessions.quality_score
  Gaps surface to council as candidate build specs
