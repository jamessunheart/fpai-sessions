## Build
Every model and tool we integrate has patterns that unlock its full potential — and anti-patterns that silently degrade it. Right now we use Claude, Codex, Fable 5, Stripe, Cal.com, Brevo, Hermes, Ollama without systematically learning their optimal use. This build creates the substrate: when we integrate a tool, the system reads its guide, extracts patterns, stores them, and injects them as context on every call to that tool. Tools get smarter over time, not static.

## New dir: docs/tool_mastery/

One file per tool/model. Each file follows this structure:
  # {tool_name} Mastery Card
  ## What it does best
  ## Optimal use patterns (concrete, with examples)
  ## Anti-patterns (what silently degrades it)
  ## Effort/parameter settings for this system
  ## Key constraints and hard limits
  ## How to detect it's not performing well
  ## Last updated + source

## New file: curator/tool_mastery/loader.py

Function: get_mastery_context(tool_name: str, max_tokens: int = 300) -> str
  Loads docs/tool_mastery/{tool_name}.md
  Extracts 'Optimal use patterns' and 'Anti-patterns' sections
  Truncates to max_tokens
  Returns compact context block: '[{tool_name} mastery] {patterns}'
  Returns empty string if no mastery card exists (graceful degradation)

Function: inject_mastery(prompt: str, tool_name: str) -> str
  Prepends get_mastery_context(tool_name) to the prompt
  Used by: ai_review.py (injects claude_review mastery), debate.py (injects claude_fable5 mastery),
  capability executor (injects tool-specific mastery per capability)

## Seed content for claude_fable5.md (use the Ferrox Labs guide content):
Key patterns to extract:
  - Brief not boss: goal + reason + hard constraints (not step-by-step)
  - Effort dial: low=chatty, high=most work (default), xhigh=hardest decisions
  - Hand over whole job, not slivers
  - Name hard boundaries plainly: 'Do not X'
  - Ask for headline first
  - If it pauses: 'continue, end to end'
  Anti-patterns:
  - Old step-by-step prompts from weaker models
  - Asking it to show/echo/transcribe its thinking as text (trips safety, degrades model)
  - Over-instructing: one targeted instruction beats a checklist
  - Maxing effort on everything (match gear to job)
  - Re-pasting context it already has
