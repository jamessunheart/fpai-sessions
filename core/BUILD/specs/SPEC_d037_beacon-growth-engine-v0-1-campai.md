## New file: curator/beacon/campaign.py

class BeaconCampaign:

  create(channel, cta_concept, audience, intent_lane) -> campaign_id
    Generates campaign_id (slug from cta_concept + timestamp)
    Creates beacon_url: {PORTAL_URL}/?b={campaign_id}
    Creates QR code PNG to /opt/fpai-build/beacon_qr/{campaign_id}.png (qrcode lib)
    Writes to brain_index.beacon_campaigns status=draft
    Triggers variant generation (see below)

  pause(campaign_id) / resume(campaign_id) / complete(campaign_id)
    Update status in DB. On pause: log to ops_ledger event=beacon_paused.

  record_event(beacon_id, event_type)
    event_type: click|chat_start|passport_created|cora_earned|first_action|proof_created|paid_conversion
    Increments counter on beacon_campaigns AND beacon_variants.
    This is called by: portal entry, onboarding/flow.py, CORA award path, proof submission.

  proof_feedback(beacon_id)
    Called when a user with this beacon_id creates their FIRST proof.
    This is the REAL conversion signal — not click, not chat_start, but proof.
    Increments proofs_created, recomputes cost_per_proof.
    Logs to ops_ledger event=beacon_proof, campaign_id=X, variant=Y.
    This closes the loop: Beacon now knows which campaign produced real value.

## New file: curator/beacon/variant_generator.py

Function: generate_variants(campaign: BeaconCampaign, n=3) -> list[BeaconVariant]

Voice loading:
  Load identity/VOICE.md from repo (SSOT for James's voice).
  Extract tone descriptors (short sentences, point-first, warmth-not-lowercase, etc).
  Pass as voice_context to prompt.

Content lanes (3 per campaign by default):
  Variant A — Focused (directly about the product/offer)
  Variant B — Adjacent (related topic, broader appeal, same audience)
  Variant C — Emotional hook (story/metaphor/curiosity, softest sell, easiest share)

Prompt to claude -p ($0):
  'You are writing marketing content in James's voice. Voice style: {voice_context}.
   Campaign: {cta_concept} | Audience: {audience} | Intent lane: {intent_lane}
   Every piece must have a trackable link or QR route home — no dead-end content.
   Generate 3 variants (A/B/C) as JSON: [{variant_label, content_type, headline, body,    cta_text, tone_score, alignment_score}]
   Be concise. Lead with the hook. Never sound like an ad.'

On generation: write to brain_index.beacon_variants, status=draft.
Send approval request to Telegram:
  'Beacon [campaign_id] — 3 variants ready for review.
   A: {headline_A}  B: {headline_B}  C: {headline_C}
   Reply: b{campaign_id}:A, b{campaign_id}:B, b{campaign_id}:C or b{campaign_id}:all'

## Pacing policy: tools/beacon/throttle.py

Function: should_scale_traffic() -> {scale: bool, reason: str, signal: dict}
Scale UP only when ALL of:
  - onboarding_completion_rate > 0.60 (from last 50 users)
  - day7_return_rate > 0.30 (users who returned within 7 days)
  - cost_per_proof trending down (last 7 days vs prior 7 days)
  - support_load < threshold (no spike in error/confusion messages)
Scale DOWN or PAUSE if:
  - onboarding_completion_rate < 0.30 (most people not completing)
  - CORA redemption rate < 0.10 (CORA not landing as valuable)
  - cost_per_proof rising 3 days in a row
  - any campaign has clicks >> chat_starts (traffic not converting to relationship)
Throttle runs in daily brief. Never auto-adjusts paid spend. Advises only.
