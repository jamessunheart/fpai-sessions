Auto-generated by the server build loop from answered decision d034.
## Build
Make Telegram the first channel adapter, not the whole system. Define a normalized message schema and gateway so WhatsApp, web, SMS, Instagram can plug in as adapters without rebuilding the brain. One relationship, many doors.

## New file: curator/hermes/__init__.py + curator/hermes/schema.py

Standard message schema (dataclass, channel-agnostic):
  @dataclass
  class HermesMessage:
    user_id: str          # universal user id (stable across channels)
    channel: str          # telegram | whatsapp | sms | web | instagram
    channel_user_id: str  # platform-specific id (chat_id, phone, etc)
    message_type: str     # text | voice | image | file | command
    content: str          # normalized text content
    beacon_id: str | None # campaign/referral source attribution
    timestamp: str        # ISO8601
    raw: dict             # original platform payload (for debugging)
    permissions: dict     # {memory: bool, marketing: bool, human_followup: bool}

  @dataclass
  class HermesResponse:
    content: str
    response_type: str    # text | image | card | decision
    channel: str
    channel_user_id: str

## New file: curator/hermes/adapters/base.py

Abstract base class ChannelAdapter:
  def normalize(raw: dict) -> HermesMessage  # platform payload -> standard schema
  async def send(response: HermesResponse) -> None  # send back through channel
  def health_check() -> bool  # is this channel reachable?

## New file: curator/hermes/adapters/telegram_adapter.py

TelegramAdapter(ChannelAdapter):
  normalize(): maps Telegram update JSON -> HermesMessage
    channel='telegram', channel_user_id=str(chat_id)
    message_type: detect voice/photo/text/command
    content: text or transcription placeholder for voice
    beacon_id: from /start payload if present
  send(): calls existing curator.telegram.send() (no change to live bot path yet)
  health_check(): verify bot token valid

Note: does NOT rewrite tgbot.py. Wraps it. tgbot.py remains authoritative for now; adapter is the translation layer for the gateway.

## New file: curator/hermes/adapters/web_adapter.py

WebAdapter(ChannelAdapter) — stub only, proves gateway works:
  normalize(): maps {user_id, content, channel='web'} HTTP POST body -> HermesMessage
  send(): returns response as JSON (no actual web UI in this build)
  health_check(): always True (local)

FastAPI endpoint: POST /hermes/web/message -> runs gateway.receive() -> routes through existing Spark/Ember pipeline -> returns HermesResponse as JSON.
This proves: same internal pipeline processes Telegram and web without knowing the difference.

## New DB table: brain_index.user_channels

Maps channel identities to a universal user_id:
  (id, user_id, channel, channel_user_id, beacon_id, first_seen, last_seen, permissions jsonb)
  UNIQUE(channel, channel_user_id)
Migration: tools/db/migrate_add_user_channels.py (idempotent ALTER/CREATE IF NOT EXISTS)
On first message from unknown channel_user_id: create new user_id (uuid), log to table.
On known channel_user_id: load existing user_id -> load Ember memory namespace for that user.
