## Changes to server_build_loop.sh

After the main build loop (after the pending check returns 0 or cap reached):
  1. Check last audit timestamp: cat /opt/fpai-build/.last_audit_date (format: YYYY-MM-DD-HH)
  2. Check merged-since-last-audit counter: /opt/fpai-build/.merged_since_audit
  3. Trigger audit IF: (queue empty AND last audit > 2 hours ago) OR (merged_since_audit >= 10)
  4. Max 1 audit per 24h (stamp /opt/fpai-build/.last_audit_date on run)

  7. Log to ops_ledger: event=self_audit, specs_generated=N, trigger=idle|merge_count
  8. Send TG: 'System self-audit complete: N improvement specs queued [audit_id]'
  9. Reset merged_since_audit counter to 0

## Audit prompt design (in self_audit.py)
The claude -p prompt must be specific, not generic. It reads the actual ledger data and asks: which of these patterns suggests a systemic gap? Categories to check: silent failures (loop ran, no work), recurring review failures (same class of issue), capability gaps (PARTIAL in architecture audit), high-correction topics (what James keeps correcting), unhealthy services.
Output format: strict JSON, 1-3 items max, each with title (< 60 chars), spec (build instructions), why (one sentence), risk_class (low/med).

## Kill switch and guards
SELF_AUDIT_DISABLE=1 skips entirely. Audit never queues: money, identity, prod-irreversible specs. If claude -p call fails or returns invalid JSON: log warning, skip, do not crash loop. Audit output capped at 3 specs per run (prevent runaway queue growth). Register in REGISTRY.json.
