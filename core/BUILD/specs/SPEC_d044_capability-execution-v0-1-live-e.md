## Build
The capability registry (d039) defines what the agent CAN do. This build makes it DO it. Three live capabilities: search_web (free), send_email (basic), book_calendar (basic). Each is a tool the agent calls mid-conversation when the user needs it. Consent required, audit logged, reversible.

## New file: curator/capabilities/executor.py

Function: execute_capability(user_agent, capability, params) -> CapabilityResult
  @dataclass CapabilityResult: {success, output, action_taken, reversible, audit_id}
  Steps:
    1. Check user_agent.can(capability) — raise PermissionDenied if False
    2. Validate params against capability schema
    3. Execute (see per-capability below)
    4. Log to brain_index.capability_log (new table, below)
    5. Return CapabilityResult

## Capability: search_web (free tier)
curator/capabilities/web_search.py:
  Uses: DuckDuckGo Instant Answer API (free, no key) or SerpAPI (key in env)
  Input: query string (extracted from user message by agent)
  Output: top 3 results with title + snippet + url
  Agent formats results as a brief summary, not raw JSON
  Consent: not required (no personal data involved)
  Reversible: N/A (read-only)

## Capability: send_email (basic tier)
curator/capabilities/send_email.py:
  Uses: existing Brevo mail stack (already in FP mail infrastructure)
  Credentials: from curator.env (already set up)
  Input: {to, subject, body} — user provides or agent drafts + confirms
  Confirmation required: before sending, agent shows draft + asks 'Send this? yes/no'
  On 'yes': send via Brevo, log to capability_log, return tracking ID
  On 'no' or timeout: cancel, log cancelled
  Reversible: NO (email sent cannot be recalled) — audit log is the safety net
  From address: user's connected email OR system relay (James configures per deployment)

## Capability: book_calendar (basic tier)
curator/capabilities/book_calendar.py:
  Uses: Cal.com API (already in FP stack for booking) OR Google Calendar API
  Input: {title, date, time, duration, attendees_optional}
  Confirmation required: show event details + 'Add this to your calendar? yes/no'
  On 'yes': create event, return confirmation + event URL
  Reversible: YES — cancel_event(event_id) removes it
  User must have connected their calendar in connected_services (consent step)

## Agent tool calling (wire into tgbot.py)
When agent detects capability intent in user message, it proposes the action:
  'I can search for that. Want me to?' [Yes] [No]
  'I can draft and send that email for you. Want me to draft it?' [Yes] [No]
On Yes: extract params → execute_capability() → return result in next message.
Intent detection: keyword patterns first (cheap), agent extraction if ambiguous.
Patterns:
  search_web: 'look up', 'search for', 'what is', 'find me'
  send_email: 'send an email', 'email them', 'reach out to'
  book_calendar: 'schedule', 'put on my calendar', 'book a time'

## Reversal support
Bot command: /undo -> shows last 3 reversible actions from capability_log
User selects one -> calls reversal function if reversible=True
For irreversible (email sent): 'That email has been sent and cannot be recalled. I have the full log if you need it.'
