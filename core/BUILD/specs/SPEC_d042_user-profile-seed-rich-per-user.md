## Build
d039 creates the namespace. This build fills it. The profile is what turns a chat session into a personal agent — the agent knows your situation, goals, patterns, proven strengths, and which paths you've actually acted on vs ignored. Every downstream feature (CORA, subscriptions, matching, capability grants) reads from here.

## New DB table: brain_index.user_profiles
(user_id text PRIMARY KEY REFERENCES user_agents(user_id),
 -- Core identity (from onboarding Spark questions)
 situation text,               -- 'what brought you here today' answer
 goals jsonb DEFAULT '[]',     -- [{goal, timeframe, status: active|achieved|dropped}]
 energy_level text,            -- full|medium|low (updated each session)
 life_areas jsonb DEFAULT '{}',-- {work, relationships, health, finances, creativity, purpose}: score 1-10
 -- Routing history (what paths were offered vs acted on)
 routing_history jsonb DEFAULT '[]', -- [{path, offered_at, acted: bool, proof_id}]
 dominant_path text,           -- which path type they respond to most (computed)
 -- Proven strengths (from proofs)
 strengths jsonb DEFAULT '[]', -- extracted from proof descriptions by agent
 -- Communication style (detected from conversation)
 preferred_tone text,          -- direct|reflective|story|analytical
 avg_message_length int,       -- short responder vs long responder
 response_speed text,          -- fast|slow|burst (session pattern)
 -- Engagement patterns
 best_session_day text,        -- Monday|Tuesday etc (which days they return)
 best_session_hour int,        -- UTC hour they're most active
 streak_days int DEFAULT 0,    -- consecutive days with a session
 longest_streak int DEFAULT 0,
 -- Connected services (granted capabilities)
 connected_services jsonb DEFAULT '{}', -- {email_provider, calendar_provider, travel_prefs}
 -- Match profile (for user-to-user matching, later)
 match_tags jsonb DEFAULT '[]', -- skills, interests, offer/need pairs
 match_open bool DEFAULT false, -- has opted into matching
 -- Metadata
 last_updated timestamp DEFAULT now()
)

## New file: curator/agent/profile.py

Function: seed_profile(user_id, onboarding_answers: dict) -> UserProfile
  Called at end of onboarding (d036 flow.py step 5).
  Runs claude -p ($0) once to extract structured fields from natural answers:
    Prompt: 'From these onboarding answers, extract: situation, goals (with timeframes),     energy_level, life_areas scores, preferred_tone. JSON only.'
  Writes to brain_index.user_profiles.
  Returns profile object.

Function: update_profile_from_session(user_id, session_messages: list) -> None
  Called after every session (async, non-blocking).
  Updates: energy_level (if mentioned), goals (if updated), routing_history (if routed),
  streak_days, best_session_day/hour, avg_message_length, response_speed.
  Never overwrites manually-set fields without confidence score > 0.8.

Function: get_agent_context(user_id) -> str
  Returns a compact context block injected into the agent's system prompt:
  '[User context] Goals: ... Situation: ... Last session: ... Proven strengths: ...   Usually responds to: {dominant_path} paths. Energy today: {energy_level}'
  Max 200 tokens. This is what makes every session feel remembered.

Function: extract_strength_from_proof(user_id, proof_text: str) -> None
  Called when user submits a proof.
  Runs claude -p to extract: what strength does this proof demonstrate?
  Appends to user_profiles.strengths.

## Context injection into tgbot.py
Before every model call for a non-operator user:
  context = get_agent_context(user_id)
  Prepend to system prompt: context block (200 tokens max).
  This replaces the global james-thread context for user sessions.
  James sessions: unchanged (james namespace, full context).
