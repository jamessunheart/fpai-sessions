## Build
brain_index (Postgres on 162) has no backup. If 162 dies, decisions, corrections, thread, tg_messages, and all training signal are gone permanently. This is the highest-risk gap in the entire system — fix it before any scaling move.

## New file: tools/infra/backup_brain.sh

Daily backup script:
  1. pg_dump brain_index -> /opt/fpai-backup/brain_YYYY-MM-DD_HH-MM.sql.gz (gzip compressed)
  2. Keep last 7 daily backups locally (delete older, save disk)
  3. Offsite copy: rsync or scp to a second location.
     Options in priority order (use first available):
     a) ~/.config/fpai/backup_destinations.env defines BACKUP_SSH_HOST + BACKUP_SSH_PATH
        -> scp to remote server (cheapest, uses existing infra)
     b) rclone to S3/B2/Cloudflare R2 if RCLONE_REMOTE defined in backup env
     c) If neither configured: log warning to ops_ledger, do NOT fail (local backup still saved)
  4. Log to ops_ledger: event=backup_complete, size_mb=N, offsite=bool, path=str
  5. On failure: log event=backup_failed, send TG alert immediately (do not wait for morning digest)

## New file: tools/infra/verify_backup.sh

Weekly verification (separate timer):
  1. Take latest backup file
  2. pg_restore --list (dry-run, does not touch live DB) -- verifies file is valid
  3. Check file age: if newest backup > 26 hours old -> alert (daily job missed)
  4. Check file size: if < 10KB -> alert (empty dump = something wrong)
  5. Log result to ops_ledger: event=backup_verified, age_hours=N, size_mb=N, valid=bool

## New file: tools/infra/RECOVERY_PLAYBOOK.md

Step-by-step recovery instructions assuming 162 is gone:
  1. Provision new server (minimum specs)
  2. Install Postgres + restore from latest backup (exact commands)
  3. Restore flat-file memory from git (already backed up)
  4. Restart services in order (with commands)
  5. Verify brain_index tables present + row counts non-zero
  6. Re-run health check
  Expected recovery time: < 2 hours from bare server
